# IVU narration: Buddy's voice and the audio system

This is the contract every screen follows when it speaks. Code lives in `src/lib/speech.ts` (the
narrator), `src/lib/buddyLines.ts` (Buddy's catalogue) and `src/ui/common.tsx` (`SpeakButton`,
`NarrationControl`, `useBuddyVoice`, `useNarration`).

## 1. Who is speaking

- **One narrator.** The IVU Reads recordings are the voice of IVU. Buddy's lines, praise and
  encouragement reuse those recordings wherever the exact words exist.
- **Buddy's personality.** Warm, curious, patient, a little playful. Buddy praises effort and
  strategy ("You did it!", "Good trying!"), never labels the child ("clever", "smart"), never
  hurries, never uses sarcasm or loss language. After a wrong answer Buddy encourages first and
  then teaches; it never says "wrong".
- **Dialogue style.** One idea per line. Short sentences a 4-year-old can follow. Say what to do
  ("Tap a world to visit it."), not how the interface works. No names inside recordable lines —
  names cannot be pre-recorded.

## 2. Where the voice comes from (hybrid plan, decided 22 Nov 2026)

Each line plays from the best source that has it, checked in this order
(`src/lib/narrationCatalog.ts`):

1. **Human voice.** IVU Reads' 500 recordings, then the IVU narrator's recordings
   (`public/narration/human.json` + `public/narration/human/`, committed).
2. **Rendered IVU voice.** Every other line, rendered once by a speech engine into audio files
   (`public/narration/rendered.json` + `public/narration/rendered/`, generated by
   `npm run narration:render`, not committed). One engine and one voice for the whole app, so
   every device sounds the same.
3. **Device voice (last resort).** Browser speech synthesis, `en-IN` preferred, at the grown-up's
   chosen voice and speed, used only when neither file exists or a file fails to play.

A passage plays from one source only: the whole passage, or every one of its sentences. If any
sentence is missing from the human recordings, the whole passage uses the rendered voice rather
than switching voices mid-passage.

**What a human records** (`scripts/narration/lines.ts`, `tierOf`): Buddy's lines, and the
questions, explanations and stories for ages 4–5 and 5–6. These are the lines the youngest
children hear most and read least. Everything else stays on the rendered voice. Human-tier lines
are rendered as stand-ins too, so nothing waits for the recording sessions.

Grown-ups can turn off the IVU voice (device voice only) or turn off all read-aloud
(Settings → Reading aloud).

## 3. Playback behaviour

- **No overlap.** Every new line stops the one before. Leaving a lesson step stops narration.
- **Pause / carry on / replay.** A `SpeakButton` that is playing becomes a pause button, then a
  "carry on" button. Lesson and revision screens have a top-bar control that pauses, resumes, or
  replays the last line.
- **Automatic vs tap.** Content (explanations, prompts, stories) auto-plays only when the grown-up
  picked "Automatically read each screen". Buddy's short feedback lines (praise, "Try again!",
  the lesson celebration) play whenever read-aloud is not off *and* feedback sounds are on.
- **Offline.** Human recordings are precached with the app. Rendered audio is too large to force
  onto every device (≈12 KB per line, ≈40 MB per age stage), so it is stored the first time
  each line plays, in its own cache (`ivu-narration-v1`) that survives app updates. Grown-ups can
  store a whole stage in advance with Settings → Voice → *Save the voice for offline use*.
- **Failure.** If a recording cannot play, the same line is spoken in the computer voice; if
  neither is available the screen still works silently — no step ever depends on audio.

## 4. Coverage is measured, not guessed

- `npm run audit:audio` writes [AUDIO_COVERAGE.md](AUDIO_COVERAGE.md): human, rendered and device
  voice shares by kind of line, world and stage, plus progress on the human recording plan. CI
  runs it with `--check`, which fails if a catalogue points at a missing file or a Buddy line
  marked `recorded: true` has no human recording. (The committed report leaves out locally
  rendered audio, so it does not change with each render.)
- Unit tests keep `buddyLines.ts` honest in both directions, and check source order, the
  no-mixing rule and the human/rendered plan.
- Each device counts lines heard in each voice and remembers the most-heard device-voice lines
  (Settings → Voice).

## 5. Rendering the IVU voice

```bash
npm run narration:render -- --stages s4,s5     # a stage or two (Buddy's lines are always included)
npm run narration:render                       # everything (about 20,000 lines)
```

Rendering can be resumed: files already made with the same voice are kept. Changing `--voice`,
`--engine` or `--rate` starts a fresh render. Engines:

- `say` (default): macOS built-in voices, voice `Tara` (Indian English). Free and offline, but
  not the most natural.
- `piper`: a local neural voice model (`--engine piper --model voice.onnx`). Needs the Piper
  program and a voice model to be installed first. Free and offline, with more natural speech.

- `elevenlabs`: the service the IVU Reads voice was made with, so it matches IVU Reads. Paid and
  online. Copy `.env.local.example` to `.env.local` (git-ignored) and fill in your API key, the
  IVU Reads voice ID (`npm run narration:render -- --engine elevenlabs --list-voices`) and model.
  `--dry-run` shows the character count, which is roughly the credits it will use. Paid renders
  over 2,000 characters stop before spending anything unless you add `--yes`. About 158,000
  characters for ages 4–5, about 1.09 million for everything.

Pronunciation fixes go in `curriculum/narration-lexicon.json` and change only what the engine
hears, not what is shown. Listen to any fix before you commit it.

## 6. Recording the human voice

1. `npm run narration:script` writes `recording-script.csv`: every human-tier line without a
   recording yet, in priority order, with its `id`.
2. The narrator records each line as `<id>.wav` (or `.mp3` / `.m4a`), using the same narrator,
   mic and room every session. Ideally this is the IVU Reads narrator.
3. `npm run narration:import -- path/to/folder` copies the files into `public/narration/human/`
   and maps them in `human.json`. Unknown IDs are reported, for example when the curriculum text
   has changed since the script was exported.
4. If a Buddy line is now recorded, set `recorded: true` in `buddyLines.ts`.
5. Run `npm run audit:audio`, then commit the audio, `human.json` and the report.

Do not regenerate or re-encode existing IVU Reads clips; add new files only.
